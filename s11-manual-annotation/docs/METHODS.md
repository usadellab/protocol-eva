# Methods of s11-manual-annotation

**Question.** How well does a large language model convert an eLabFTW protocol entry into an ISA assay table with the elab2arc extraction prompt? The supplement of the elab2arc publication (S11, `docs/Supplement_S11_manual_annotation_comparison.docx`) reports prompt version 6; this section adds the data, the code and the other experiments behind it.

**Entries.** Five eLabFTW entries (bacteriophage sequencing, spot assay, strain generation, BioLector cultivation, plasmid generation), converted to markdown as the application does it (HTML to markdown, `datasets/protocol_inputs/`).
The published protocol inputs and annotation spreadsheets were de-identified after the runs: names of experimenters and of the collaborators who provided the samples, affiliations and the links to the institute eLabFTW server were removed or replaced by neutral text. The models saw the original input text; the scores do not depend on the removed text (the removed text is not scored).

**Published as is: protocol texts and curator annotations (owner decision 2026-10-09), including entry ids and relative eLabFTW links in the text** (`experiments.php?mode=view&id=<id>` in `datasets/protocol_inputs/` and in the `prompt` field of `image_addition/captions/`; short tags and initials in annotation cells). Only names of persons, the provider institution, affiliation, the institute server host and absolute eLabFTW links were removed.

**Manual annotations.** Manual annotation B (`datasets/manual_annotations/*_B_curator.xlsx`) was made independently by a DataPLANT curator for all five entries and is the reference of every score. Manual annotation A (`*_A_authors.xlsx`) was made by the study authors, who also wrote the extraction prompt; it exists for the bacteriophage entry (agreement of A and B: `datasets/manual_annotations/agreement_A_vs_B.csv`).

**Terms.** *Row* (record): a row of any table of the assay (samples sheet or process sheet). *Cell*: one non-empty value cell of the columns Characteristic, Parameter, Factor, Comment and Date; a value and its unit count once. *Cell human*: number of cells in manual annotation B of an entry. *Cell AI*: number of cells in the answer of a model.

**Metric.** Record-level precision, recall and F1, counted in cells. The rows of all tables of the answer are paired one-to-one with the rows of the manual annotation (Hungarian assignment that maximises the number of matched cells); the cells of each pair are then compared after normalising decimal comma, units (to base units), dates, case, a leading "~" and a leading quantity followed by explanatory text. Matched cells are true positives; cells of the answer that match nothing are false positives; cells of the manual annotation that nothing matches are false negatives; all cells of an unpaired row are errors of the corresponding kind (an invented row lowers precision, a missed row lowers recall). A **failed run** (invalid or truncated JSON, no usable answer) scores 0 over the full annotation. An **endpoint error** (rate limit, quota, server down, refused request) is not a model failure: the run was discarded and repeated, never scored. The score of an entry is the mean over its repeats, the score of a model is the mean over the five entries (equal weights).
Implementation: `scripts/28_score_extraction.py`. Independent second implementation: `scripts/verify_scores.py`. Both pair the rows with the Hungarian method; they differ in the matching of cells inside a pair (28: maximum matching by augmenting paths with three compatibility rules; verify: `scipy` assignment) and in the unit table (each has its own).

**Routes.** Claude Opus 5.5 and Sonnet 5.5 through the Claude Code CLI in print mode (`scripts/46_claude_cli_extract.py`); Kimi-K3 through the Kimi Code CLI, an agent harness (`scripts/37_kimi_cli_extract.py`); DeepSeek-V4.1-Flash through a hosted API; open-weight models locally on a Mac (LM Studio, oMLX), on the institute GPU cluster with vLLM (`scripts/cluster/`) and through free-tier OpenRouter endpoints. `scripts/26_llm_extraction.js` runs the application's own LLM module headless and sends one request per run; the answer is parsed as strict JSON without repair. Sampling parameters: `results/v6/sampling_parameters.json`. Which csv label belongs to which row of Table S11-2: `results/v6/model_label_map.csv`.

**Data snapshot.** All numbers in this section come from the per-run scores of the data snapshot 2026-10-08 12:05 (410 text-only runs of the five entries, all prompts, `results/runs.csv`; 115 runs with figure descriptions or images, `image_addition/`). Runs made after the snapshot (reruns of runs that had exhausted the output budget) are not included and are not in the supplement. Only the models that are rows of Table S11-2 are part of this section; runs of other models made in the study (labels removed by the authors from the table, models run on fewer than five entries) are not included.

**Prompt versions and extended experiments.** `benchmarking_versions/` (prompt texts and their scores), `traceable/` (evidence quotes), `image_addition/` (figure descriptions, real images). Only prompt version 6 is reported in Tables S11-1 and S11-2; the other experiments support the statements of the text of the supplement (`scripts/recompute_statements.py`).

**Terminology in the code.** The scripts were written under another name for the manual annotation; in this section the word was replaced by "annotation" (`annotation`, `annotations` in identifiers, columns and messages) and the scorer and the verifier were run again after the renaming with identical results (see `docs/REPRODUCE.md`).
