The name prefix is the run's own date or label as written next to that run, not the entry's creation or title date. Runs that use the same procedure share one protocol per step; a changed procedure is a separate protocol. Preparations (media, reagents, dilution series) and side procedures such as sending material for sequencing are protocols of their own, with the materials used as inputs. If no samples are named, create generic names. Fill organism and characteristics; use the ontology fields termSource and termAccession when known, otherwise empty strings.

2. Parameters: extract every parameter stated in the protocol: physical measurements, concentrations, volumes, times, equipment settings, thresholds, and, for computational protocols, software names and versions, command-line arguments, file formats and reference databases. Include an implied parameter with empty value and unit rather than skipping it, but never invent a value. When a value differs between the rows of a step, write value as an array with exactly one entry per row, in the same order as inputs and outputs, and write evidence as an array of the same length; otherwise use single strings. Record measured values on the step where they were measured, not in sample characteristics. Never summarise differing values into ranges and keep every recorded measurement. Use the entry's own labels for materials and parameters.

3. Conditions are rows, never columns. When several conditions are tested on the same samples, create one row per sample times condition, repeat the inputs, and give the condition as a per-row parameter. Do not create numbered parameters or parameters whose name contains a condition.

4. Granularity: write one protocol per procedure that the entry describes as its own part. A reading, measurement or check taken during or after a procedure is a parameter of that procedure, with one value per row, like the final OD in the example; it is not a protocol of its own. A check becomes a protocol of its own only when the entry describes it as a separate procedure with its own method, materials or file, like the quality control in the example; this is the exception.

Linking: the inputs, outputs and dataFiles arrays of one step have the same length; repeat an entry where needed (one input giving several outputs: repeat the input; several inputs giving one output: repeat the output). The next step takes as inputs the materials that really continue: the outputs of the step before, or, when the step before only measured or checked the samples and produced files or reports, the same sample names again. A step that only produces a report or image names that report or image as its outputs and lists the file in dataFiles. A step that really changes the material gives its outputs new names: the sample name plus the step. Use specific names, not generic terms. Tools and software are parameters, not outputs.
